# NeoOrg 参赛演示视频方案

视频围绕未来办公中的协作成本展开：即使每个人都能得到 AI 回答，人类仍可能要反复搬运上下文、协调分工、跟进修改和确认结果。NeoOrg 的方案是在同一个群里组织人类和有岗位的 Agent，让目标有持续负责人、专业贡献按需发生、交付接受独立评审。案例用来证明这些机制，问题、方案、差异化和技术解释共同组成主线。

本轮交付策划方案，尚未录制或生成成片。PPT、发布视频、填写表单和最终比赛提交不在本轮范围。

## 赛道问题与方案优势

Future of Work 关注知识获取、协作、决策和日常工作完成。视频聚焦其中的跨专业协作：信息变了以后，谁同步、谁继续负责、谁确认交付符合要求。片头用业务困境和简短动效建立问题，不用无依据的统计数字。[官方赛道定义](https://aibuildercup.com/themes.html)

核心表述是“把 AI 从一次性回答的入口，组织成能共同交付结果的团队成员”。相比一次性聊天，本方案把岗位、负责人、贡献和验收条件明确保留下来；相比预先规定所有发言顺序的流水线，负责人按目标请求需要的贡献，并在等待人类输入时保留责任。这是本产品的机制选择，不是声称其他产品都缺少这些能力，或多 Agent 已被证明比单 Agent 更快、更准确。

技术段要解释机制如何落地：Gemini 处理目标理解、专业内容和评审语义；应用维护负责人、贡献资格、验收条件、状态和恢复；Firestore 持久化消息、目标、交付和检查点；Cloud Run 提供实际部署。画面将业务步骤与这些组件对应起来，不只展示云服务 Logo，也不把独立评审说成独立模型或客观正确性的保证。

## 案例甄选

| 候选 | 差异化潜力 | 当前原型的证明边界 | 取舍 |
|---|---|---|---|
| 单次试点 Go / No-Go 建议 | 中等；容易被看成一轮问答 | 可真实完成有评审的文本建议 | 留作备用，不作为主片主线 |
| 客户交付前发生约束变更的跨专业小队 | 能展示持续负责人、事实冲突、人类补充和独立验收 | 可真实交付客户承诺文本、范围与验收清单；不执行上线 | 推荐主案例 |
| 创作团队交付短片 | 可见成果强，适合展示专业交接与改稿 | 当前可协作完成脚本/分镜；渲染成片需要外部制作流程 | 候选二；避免被理解成媒体生成工具或假称一键成片 |
| 产品设计、研发和 QA 自动发布软件 | 生产团队差异鲜明 | 当前参赛部署没有代码执行、测试与发布工具 | 可作明确标注的愿景，不能当作已部署功能实录 |

主案例必须出现对同一成果有影响的协作，而不只是四个 Agent 各写一段。优先呈现事实与承诺的冲突、一次需要人类确定的业务取舍，以及独立评审对验收条件的逐项检查。模型若已经识别风险并直接交付合格内容，就忠实展示；不故意要求模型先犯错，再安排假返工。

## 演示场景

身份是负责周五向客户交付试点的业务负责人。场景明确标为 `Synthetic demo case`：客户已被口头承诺全面开放，但同一版本的五个测试团队中只有四个独立完成 onboarding，一个仍需协助，重复恢复测试也尚未完成。支持资源还需要人类确认。这些是演示输入，不是客户数据或产品实测业绩。

新建 `Client pilot delivery` 群聊并选择四位 Agent。Harbor 的协调岗位负责推进，Reef 基于提供的材料核对事实，Sail 提供交付策略与安排，独立成员按条件检查最终承诺和验收清单。岗位介绍沿用真实目录，不把现有 Agent 临时包装成已接入代码工具的研发或测试人员。实际负责人、贡献者和评审者以真实运行分配为准，贡献者不同时承担该交付的独立评审。

建议的首条任务如下，正式文案在彩排后定稿：

> @Harbor Prepare a client-ready pilot handoff for Friday. Synthetic demo case: the client was promised a full rollout, but five teams tested the same build, four completed onboarding independently, one needed operator help, and repeated recovery testing is not complete. Coordinate useful teammate contributions using only these facts. Before final delivery, ask me to confirm support capacity and non-negotiable constraints. Deliver a concise customer-facing commitment, an explicit in-scope/out-of-scope handoff, and an acceptance checklist with responsible roles and exit conditions. Do not turn unverified claims into facts or claim that testing, sending messages or rollout actions have occurred.

关键协作片段是负责人询问资源，系统显示等待人类输入，再由用户补充：`Only two teams can receive support next week. Friday cannot move, and we cannot add staff. Narrow the promise instead of assuming a full rollout; make the recovery check an exit condition before expansion.` 负责人保持同一目标的责任，把事实、专业贡献和新约束整合成正式文本交付。最终画面能读到给客户的承诺措辞、范围边界和验收清单，而不是只看到“任务完成”。

这个等待与继续必须在真实彩排中出现。若模型没有产生 input gate，不把普通新聊天剪成“同一目标恢复”，也不修改 Firestore 或响应文本来配合脚本。先调整明确的业务任务表述并重新完整录制；若仍不稳定，主片保留已验证的真实协作主线，将输入门从必拍镜头降为候选，不为拍片临时改产品。

## 三分钟分镜

| 时间 | 画面与叙事 | 观众需要看懂的事实 |
|---|---|---|
| 0:00–0:25 | 情境化片头：承诺、事实和资源散在不同对话里，人类持续协调；扣住未来办公的协作成本 | 问题是跨角色的工作组织和结果确认，不是缺少一个会回答问题的模型 |
| 0:25–0:50 | NeoOrg 方案动画与少量真实界面：岗位、共同目标、持续负责人、按需贡献与独立评审 | 产品选择了哪些协作机制，以及为何适合这类工作 |
| 0:50–2:00 | 真实客户交付案例：发起目标、专业贡献、真实人类补充约束、最终交付及评审；建群操作短切展示 | 同一目标的责任和约束持续存在，结果经过检查；留时间看清交付正文 |
| 2:00–2:35 | 技术机制示意配实际发布/调用证据：Gemini 语义判断、应用规则、Firestore 持久化、Cloud Run 部署 | 技术如何支撑前面的协作，而不只是多角色 Prompt 和云服务图标 |
| 2:35–3:00 | 回到交付与验收结果，归纳机制优势、当前边界；可用不超过约 5–8 秒的明确标注愿景，最后展示作品入口 | 当前原型已证明什么、哪些属于后续扩展；最终业务决定仍由人作出 |

真实案例占 70 秒，问题、方案、技术和价值解释占其余 110 秒；这是制作安排，不是官方规定的时长配比。英文旁白先按约 330–360 词试读，再用实际语音时长调整。录屏允许压缩等待并注明，但不把剪辑后的秒数宣传为完整任务耗时。2:55 备份主要缩短开头与结尾，不删除独立评审或技术证据。

## 虚构与概念演绎边界

可以设计虚构企业、业务角色、约束冲突和演示数据，也可以用动画解释完整产品理念。视频无需全部由当前界面录屏组成；是否真实运行与是否情境化创作必须让观众区分清楚。

| 画面类型 | 用法与标识 |
|---|---|
| 虚构业务案例 | 标注 `Synthetic demo case`，其数字不作为客户成绩或效果证明 |
| 方案、架构与责任关系动画 | 采用明显的解释性视觉；描述当前机制时与已实现功能一致 |
| 未实现功能的交互演绎 | 场景开头和画面内持续标注 `Product vision — not in the current prototype`，旁白使用未来语气，不混为真实录屏 |
| 当前部署功能实录 | 以真实运行和持久化结果为准；剪辑不替换模型正文、负责人、评审意见或状态 |

例如自动接入企业系统、开发上线软件、由 NeoOrg 自动渲染成片，可以出现在明确的愿景段，不能承担核心功能证明。若拍摄原版 NeoOrg 的其他真实能力，也要说明版本与参赛部署的区别，不能让评委以为提交链接包含它。优先选核心差异已经能在当前部署中证明的案例，不用长篇概念演绎弥补工作原型缺失。[官方工作原型要求](https://aibuildercup.com/themes.html)

## 制作工具甄选

HyperFrames 和 Remotion 是同一层的可编程视频合成方案，不是必须叠加的工具。两者均可混合实拍录屏、文字、图形与声音；视觉效果取决于分镜、素材和设计，不能仅凭框架名称判断成片质量。

| 工具 | 已核实的能力与本片用途 | 取舍 |
|---|---|---|
| HyperFrames | HTML/CSS 与可定位时间的动画、音视频轨道、浏览器预览、逐帧渲染；适合问题/方案/架构动效和录屏混排 | 主合成候选；官方项目为 HeyGen 的开源框架，Apache-2.0 |
| Remotion | React 组件管理视频时间线；Recorder 提供录制、字幕与剪辑工作流 | 替代方案；若其混合媒体样片更稳定则改用，不为同一片强行维护两套时间线 |
| OBS 单窗口录制 | 录制实际产品浏览器窗口，保留完整母带 | 录制工具，不代替视频合成；关闭无关桌面音频和麦克风来源 |
| Gemini TTS | 用英文脚本生成旁白，先试音色、术语读音和语速 | 单独配置 TTS 模型、凭证与额度；不假设现有文字模型可直接配音，不默认增加付费服务 |
| FFmpeg 与 ffprobe | 媒体处理与检查，核对片长、音视频轨、编码、分辨率；字幕另交 SRT | 成片处理和验证，不是方案创意或业务功能来源 |

一手资料：[HyperFrames 源码](https://github.com/heygen-com/hyperframes)、[产品视频](https://hyperframes.heygen.com/guides/product-launch-video)、[动效](https://hyperframes.heygen.com/guides/motion-graphics)、[声音字幕](https://hyperframes.heygen.com/guides/voice-and-audio)、[Remotion Recorder](https://www.remotion.dev/docs/recorder/)、[OBS](https://obsproject.com/kb/quick-start-guide)、[Gemini TTS](https://ai.google.dev/gemini-api/docs/speech-generation)、[ffprobe](https://ffmpeg.org/ffprobe.html)。

开始制作时，先以同一段 15–20 秒素材核验主合成器：品牌片头、一个责任关系动效、真实录屏、英文旁白与字幕，输出一次 1080p MP4，检查取帧、字体、可读性、音画同步和片长后锁定工具。当前尚未进行本机渲染对比，HyperFrames 首选是基于本片解释动画占比的适配判断，不是性能测试结论。

不需要同时引入 HyperFrames、Remotion 和另一套商业剪辑软件。先选一个主合成器，配录屏、配音和验证环节即可。若使用 HyperFrames，本地渲染与可选托管/语音/媒体服务的费用分开；若改用 Remotion，先核对使用主体的许可资格，不能把参赛团队人数当作公司员工数。[HyperFrames 本地与服务说明](https://hyperframes.heygen.com/quickstart)、[Remotion 许可](https://www.remotion.dev/license)

## 录制与剪辑方式

1. **先定台词和样片。** 输出英文逐镜头脚本、中文审阅释义和 15–20 秒风格样片，确认叙述是否清楚、字幕能否读清、音色是否合适。默认不要求用户出镜或录音。
2. **再跑真实场景。** 使用独立、只含演示数据的浏览器会话与新群聊，在当前已部署 Cloud Run 产品调用真实 Gemini，核对同一目标的 owner、贡献、交付、评审和刷新持久化。只使用提供的材料，不暗示 Reef 做了未接入的联网检索。
3. **录完整母带。** 从建群到结果保留连续原始录制及对应运行记录，剪辑选择来自同一次业务链。若真实请求失败，保留证据，按系统正式恢复动作处理；不拼接不同运行来伪造连续成功。
4. **合成可编辑时间线。** 按小样结论选择 HyperFrames 或 Remotion，管理录屏片段、解释动画、字幕、标注和技术示意。沿用 NeoOrg 当前 Logo 与蓝灰视觉，真实功能与概念场景采用明确区分的画面标签。
5. **完成两轮验收。** 先审阅叙事和事实，再审阅正式输出的清晰度、字幕、音量、精确片长和可播放性。最后交付主版、时长备份、字幕、封面和可编辑工程。上传平台后的公开访问检查另行进行，不能在上传前宣称已通过。

视频工程与产品依赖、部署链路隔离。本轮未安装录屏/合成工具或配置 TTS；已有 Node/pnpm 和系统语音只代表可用于后续准备，不代表视频生产链已经跑通。正式旁白优先验证可用的 Gemini TTS，系统语音仅可作为节奏样轨；不克隆真人声音，不默认购买配音或音乐。第一版可不加音乐，保证旁白与产品信息优先。

## 事实与画面验收

- 功能实录来自当前已部署 NeoOrg，概念场景单独标注；录制前重新核对发布版本。真实 Gemini 调用以对应任务的调用记录和交付为依据，健康端点只能证明配置与存储探测，不能单独证明推理成功。
- 负责人始终可识别；贡献者不关闭目标，评审者不参与该交付的创作。实际角色与屏幕标注一致。
- 人类补充输入必须消费真实等待中的目标；负责人和旧消息保留。已完成目标后的新消息不能被包装成自动恢复旧目标。
- 最终建议可读，有事实缺口、行动与验收条件；`Reviewed · Goal achieved` 不能旁白成“试点已成功上线”。本原型交付文本，不执行上线、测试、发邮件或外部系统写入。
- 不把 Firebase Hosting/Authentication、独立 Worker/PostgreSQL、长期记忆或完整 NeoOrg 平台说成当前部署能力。Firestore、Cloud Run 和 Vertex AI 的作用与现有实现一致；愿景动画不是新增功能证据。
- 不露出 room token、访问凭证、私人浏览器标签或无关项目数据。技术证明使用脱敏的发布/调用片段，不录制环境变量和密钥页面。
- 英文字幕不遮住输入区和验收结果；缩到 1280×720 仍能读到核心信息。逐镜头检查片首、片尾、转场与音画同步，全片正常速度试听。
- 合成场景数据与正式模型输出来源可区分；不伪造客户、节省时间、多 Agent 优势或基准成绩。原片中的等待如被压缩，画面注明。
